## Problem Statement

The repo has been a junk drawer for over a decade. It doesn't have one big bug. It has drifted away from the machine it's supposed to describe:

- **The install step needs Ruby before the dotfiles exist.** `Rakefile` symlinks 14 entries (`LINK_FILES`), inserts a `# START GENERATED … # END GENERATED` block into `~/.gitconfig` and `~/.gemrc`, touches `~/.psqlrc.local`, and backs up conflicting files to `~/dotfiles-bak`. It has drifted: `railsrc` isn't in `LINK_FILES` and was linked by hand (`~/.railsrc`, Jun 2026).
- **Scripts live in two places.** `~/bin` is a separate real directory, not a link to `dotfiles/bin`. 5 scripts are copies of repo files, 8 repo scripts were never installed, and about 10 exist only in `~/bin` (`video-transcode-batch.rb`, `video-rename-files.rb`, `synergy-start`, `old-git.sh`, `hb`...), mixed in with AppImages.
- **Nothing under `~/.config` is tracked.** That includes kitty, nvim, mise, git, gh, opencode, fish and zed. The repo predates XDG.
- **Machine-level AI config isn't tracked.** `~/.claude/settings.json` and `statusline-command.sh` aren't in any repo. `~/code/claude-config` holds the portable layer (CLAUDE.md and the darren plugin) and serves Windows too.
- **Shell load order is split oddly.** `bash_profile.d/*.sh` (functions like `dns`, `first_of`, `meta`, `switch`) only loads in login shells. `bashrc.d/*.sh` loads in interactive shells. Both are looped with `` for a in `ls ...` ``.
- **`gitconfig` has a live hazard:** `push.default = upstream`, which `~/code/claude-config/CLAUDE.md` names as the cause of a branch going straight to `main`. It also still sets `editor = mvim` and `diff.tool = gvimdiff`.
- **Fossils:** a vendored 2,275-line `bash_profile.d/git_completion.sh`, `osx`, `slate`, `spacemacs`, `emacs.d`, `rvmrc`, `nixpkgs/`, xenial-era `etc/sources.list.d/*`, and `TODO` (Slate → mjolnir).

Goals, in your words:
1. "Reorganize everything in here so that it has a modern shape", so you can then go file by file and clean up.
2. A better bootstrap than a Rakefile that needs Ruby first, likely based on mise.
3. "Find the things that aren't here, that should be", especially AI tooling.
4. A clear rule for functions vs. scripts, and one place for small scripts, without "the pain of two repos".

## What Makes This Cool

mise, which you just moved to from asdf, already does the dotfiles manager's job. mise 2026.6.6 added `mise bootstrap` and `mise dot`. Both are confirmed in your installed `mise 2026.11.2`:

- `mise dot add` moves a live file into the repo and links it back. That's adopting with one command (used here as `dot add --local --source <repo-path> <target>`, see Key decisions).
- `mise dot status` / `mise dot diff` show where the machine differs from the declared config.
- `mise bootstrap` applies apt sources and packages, repos, dotfiles, shell activation, tools, and a final `bootstrap` task, in a fixed order. It has `--dry-run`, `plan` and `status --missing`.

So nobody has to write a `dot` tool. Stow, chezmoi and the Rakefile all go. The one gap is **undeclared** drift: configs and scripts mise was never told about. A ~50-line `doctor` task fills that gap. Cleanup then becomes a list that gets shorter: run doctor, then adopt, ignore, or delete each line.

## Constraints

- Linux-first (Pop!_OS, bash). Windows stays out of scope. claude-config remains its cross-platform layer.
- You review every change as an unstaged diff. Work goes on `darren/<topic>` branches; no commits without asking.
- Secrets never enter the repo (`gh/hosts.yml` holds a token; `~/.claude/settings.json` may grow an `env` block). gitleaks guards commits and doctor; values are never printed.
- Every phase must leave a working shell. A broken `.bashrc` locks you out of new terminals.
- `mise dot` / `mise bootstrap` are about five months old. Pin the behavior we rely on with checks, not faith.

## Premises (agreed)

1. mise is the dotfiles manager. A repo-root `mise.toml` with `[dotfiles]` replaces the Rakefile. A fresh box needs two commands: install mise, then `mise bootstrap --from <repo> --from-dir ~/code/dotfiles`.
2. The repo takes an XDG shape: `home/` for files that must sit in `~`, `config/<app>/` mirroring `~/.config/<app>/`, `bin/` for scripts, `archive/` for fossils until you review them. Moving files is the reorganization. Deleting is your later pass.
3. Scripts live in `dotfiles/bin`, and `~/bin` is a symlink to it. A function is only for something that must change the current shell (cd, env vars, prompt, completions). Everything else is a script.
4. Undeclared drift is the one gap mise doesn't cover. A `doctor` task closes it.
5. AI config is split by role. claude-config keeps CLAUDE.md and the plugin. dotfiles adopts the Linux machine layer, with secrets excluded.
6. `push.default = upstream` (and `mvim`) get fixed during the move.

## Approaches Considered

- **A: Rehome in place.** Swap the Rakefile for `mise.toml`, keep the flat layout. Rejected: leaves the junk-drawer shape, and `~/.config` stays invisible.
- **B: XDG repo, mise bootstrap and doctor, in phases.** Chosen.
- **C: Track first, move later** (`mise dot track` everything in place). Rejected: mise's tracked history becomes a second source of truth, which is the two-repo pain again.

## Recommended Approach: B, in phases

This section reflects every decision through the eng review (D2–D11 of `/plan-eng-review`; the ledger below has the reasoning).

### Target layout

```
dotfiles/
  mise.toml          # [dotfiles], [bootstrap.*], repo [tools] (gitleaks), [tasks] — the whole machine
  mise-tasks/        # repo tasks: doctor, dot/check (run anywhere via `dotrun doctor`, `dotrun dot:check`)
  doctor.ignore      # ~/.config entries you decided not to track
  .gitleaks.toml     # reviewed allowlist for the secret scan
  githooks/          # pre-commit (gitleaks); core.hooksPath points here
  home/              # ~/.X files: bashrc, bash_profile, profile.d/, bashrc.d/, inputrc, irbrc(.d),
                     # psqlrc, gemrc, railsrc, rails-console-rc(.d), xsessionrc, editrc,
                     # aprc, npmrc, guard.rb
  config/            # mirrors ~/.config: git/{config,ignore}, mise/config.toml (global tools),
                     # kitty/, nvim/, gh/config.yml, opencode/ ...
  claude/            # ~/.claude machine layer: settings.json, statusline-command.sh
  bin/               # every personal script, on PATH via ~/bin -> dotfiles/bin
  templates/         # rails_template.rb
  docs/              # README, linux notes, POSTGRES, PYTHON, troubleshooting, mise-notes.md
  archive/           # fossils awaiting your review (osx, slate, spacemacs, rvmrc, git_completion.sh, ...)
```

### Key decisions

- **The repo-root `mise.toml` owns the machine.** It holds `[dotfiles]`, `[bootstrap.*]`, the tools the repo's own tasks need, and `[tasks]`. Keeping it at the root means:
  - every `source` stays repo-relative, because mise records sources relative to the config file's directory when they're inside it and as absolute paths otherwise;
  - `mise bootstrap --from` works as documented (it expects a repo with a `mise.toml`);
  - global writes like `mise use -g` and `mise settings set` stay out of the checkout.

  Repo-level config is read only after `mise trust`, and only from inside the repo or with `-C`. Two aliases in `bashrc.d` cover that:

  ```bash
  alias dot='mise -C ~/code/dotfiles dot'
  alias dotrun='mise -C ~/code/dotfiles run'
  ```

  Adopting writes to the repo, never the global config: `dot add --local --source config/kitty ~/.config/kitty`. A plain `mise dot add` defaults to the global config and to `dotfiles.root = ~/.dotfiles`, so don't use it.
- **Global tools live in `config/mise/config.toml`.** It's an ordinary dotfile, deployed to `~/.config/mise/config.toml`, and it's where this repo keeps global tools. It uses `mode = "copy"` if `mise use -g` rewrites it, and `dot add` copies those edits back. `mise bootstrap` installs these global tools itself [measured: phase 0, docs/mise-notes.md].
- **Git config moves to `~/.config/git/config`, owned by the repo, with no insertion.**
  - Git reads `~/.config/git/config` first and `~/.gitconfig` second, so later values in `~/.gitconfig` win. Phase 1 therefore deletes the old `# START GENERATED … # END GENERATED` block from the live `~/.gitconfig`, leaving only machine-local bits (user.email, credential helpers).
  - `push.default = simple`: a bare `git push` on a `--no-track` branch refuses, so pushes go through your explicit refspec. Check: `git config --show-origin --get-all push.default` prints exactly `simple`, from `~/.config/git/config`.
  - `editor = vim`.
  - The `ec` alias opens the repo file.
  - The existing `~/.config/git/ignore` merges with the repo's `gitignore` into `config/git/ignore`, and `core.excludesfile` is dropped.
- **`gemrc` moves to a mise-managed edit.** Before the first apply, delete the old GENERATED block from the live `~/.gemrc`, so the file never holds two managed blocks with duplicate YAML keys. Block mode is `"~/.gemrc/dotfiles" = { source = "home/gemrc", template = "tera" }`; it writes `# >>> mise:dotfiles >>>` … `# <<< mise:dotfiles <<<` and does not remove the old block [measured: phase 0]. Check: `~/.gemrc` has exactly one managed block, or is the symlink.
- **Two shell layers, by who needs them.** Shells that don't read `.bashrc` (`bash -lc` from Claude Code, editors, cron) still need PATH and env, and `bashrc` returns early for non-interactive shells. So:
  - `home/bash_profile` sources `home/profile.d/*.sh` (env and PATH only), then `~/.bashrc`. This flips today's order, where `.bashrc` loads first. It's intended: env is in place before interactive setup. dot:check asserts that `ruby` resolves to a mise path in both shell kinds.
  - `home/bashrc.d/` holds everything interactive: functions, aliases (including `dot`/`dotrun`), completion, prompt, history, and `mise activate`. Files get numeric prefixes for load order.
  - Both loops skip missing files, so an empty directory on a half-applied box doesn't break the shell: `for f in ~/.bashrc.d/*.sh; do [ -r "$f" ] && . "$f"; done`.
  - The rule is per file, not per directory: a file that `export`s a variable or changes `PATH` goes to `profile.d`; anything else goes to `bashrc.d`. A file that mixes both gets split. Phase 2 starts by running `grep -lE 'export|PATH'` over both directories. Known today:

    | Destination | Files |
    |---|---|
    | `profile.d` | `mise_shims.sh`, `flyio.sh` (`FLYCTL_INSTALL`, `~/.fly/bin`), `postgres.sh` (`PGDATA`, `PGHOST`), `standard_settings.sh` (`GOPATH`, `$GOPATH/bin`), new `ssh.sh` (below), plus `~/.local/bin`, `~/bin`, cargo, EDITOR/VISUAL from `bash_profile` |
    | `bashrc.d` | `dns`, `first_of`, `meta`, `switch`, `color_man`, `completion`, `whiteboard_cleaner`, `python` (from `bash_profile.d`; aws completion only), and the current `bashrc.d` files that set nothing (`current_project`, `git`, `mise`, `pg`, `prompt`, `python`, `standard_improvements`) |
    | Split by line | `history.sh`, `colors.sh`, `ruby.sh`, `standard_aliases.sh` |

  - **Machine-local hooks:** `~/.profile.local` and `~/.bashrc.local`, each sourced only if present, never in the repo. They replace the Rakefile's `~/.bash_profile.d/local.sh` convention and are added in phase 1 (step 3), because the git-ignored `local.sh` files don't move with `git mv`.
- **SSH agent: use the desktop's agent.**
  - The `ssh-agent` block in `bash_profile` is deleted. Today it starts its own agent with a cwd-relative state file.
  - `home/profile.d/ssh.sh` exports `SSH_AUTH_SOCK="${SSH_AUTH_SOCK:-$XDG_RUNTIME_DIR/gcr/ssh}"`, which points at Pop!_OS's `gcr-ssh-agent`.
  - Phase 2 check: `ssh-add -l` lists your key, and `ssh -T git@github.com` authenticates.
  - If that check fails, fall back: keep the block, use `$HOME/.ssh/ssh-agent` as the path, and skip the block when `XDG_RUNTIME_DIR` is unset.
- `git_completion.sh` goes to `archive/` like the other fossils, and the distro's `/usr/share/bash-completion` takes over.
- **Every Rakefile behavior gets a replacement** before the Rakefile goes:

  | Rakefile behavior | Replacement |
  |---|---|
  | `LINK_FILES` symlinks | `[dotfiles]` entries, inventoried from the live `~` and `~/.config` (every symlink into the repo), not from the Rakefile list |
  | GENERATED block in gitconfig/gemrc | `config/git/config` and the gemrc decision above, with old blocks stripped |
  | `touch ~/.psqlrc.local` | the `bootstrap` task creates it if missing (`psqlrc`'s `\i ~/.psqlrc.local` errors without it) |
  | `~/.bash_profile.d/local.sh` hint | `~/.profile.local` / `~/.bashrc.local` |
  | backup conflicting files to `~/dotfiles-bak` | `mise dot apply` refuses the whole apply when any target is a real file (exit 1), silently replaces dangling links, and `--force` overwrites without a backup [measured: phase 0]. Phase 1 copies every conflicting non-symlink target (including the real `~/.config/mise` dir) to `~/dotfiles-bak` first |
- **Functions → scripts by the rule.**
  - Become `bin/` scripts: `myip`, `dns`, `show_table`, `first_of`, `pathsplit`, `whiteboardCleaner`.
  - Git helpers (`ggc`, `grb`) become `bin/git-ggc`-style scripts or git aliases, since git runs any `git-*` found on PATH.
  - Stay functions: `switch`, `o`, `meta`, anything that `cd`s or exports, prompt helpers, and `man`.
- **Script conventions.** `bin/` stays flat. Every script has a shebang, the executable bit, and a one-line purpose comment on line 2. Ruby scripts use `#!/usr/bin/env ruby` and resolve through mise shims. AppImages move to `~/Applications` (or are installed via mise/apt where possible), not `bin/`.
- **Symlink vs copy, per app.** Symlink is the default. Apps that rewrite their config with an atomic rename replace the symlink with a regular file. Use `mode = "copy"` for those, and `dot add` copies edits back to the source. Likely copy candidates: `claude/settings.json` (the tools leave `.bak` files beside it), kitty's `current-theme.conf`, `config/mise/config.toml`. Verify each one in phase 4.
- **The live checkout is the live config.** `~/.bashrc` and friends are symlinks into `~/code/dotfiles`, so whatever branch is checked out there is what every new shell loads. Rules:
  - The in-flight asdf→mise work is committed (on its own `darren/<topic>` branch, merged first) **before** phase 1 starts.
  - From phase 1's apply until `darren/modernize` merges, the live checkout never switches branches. Work that needs another branch uses `git worktree add`, never `git switch` in the live tree.
- **Phase isolation.** Phases 1 and 2 are checked on the real machine with `dot diff` before `apply`. Bootstrap is checked in a throwaway Ubuntu container, never on the live box first.
- **Secrets: gitleaks, never reading values.**
  - `gitleaks` is a repo `[tools]` entry.
  - `githooks/pre-commit` runs `gitleaks git --pre-commit --staged --redact`.
  - Doctor runs `gitleaks dir --redact` on `claude/`, `config/gh/`, `config/opencode/` and `config/mise/`.
  - Reviewed false positives go in `.gitleaks.toml`.
  - Git doesn't version `.git/hooks`, so the `bootstrap` task (and phase 4, by hand on this machine) runs `git -C ~/code/dotfiles config core.hooksPath githooks`. Doctor reports it if that's unset.
  - No agent or command `cat`s a candidate file. Inspection shows key names only (`jq -r 'paths|map(tostring)|join(".")'` for JSON); you look at any match yourself.
  - `.gitignore` lists `config/gh/hosts.yml` and `**/*.local`.
  - Proof: in a scratch `git worktree`, committing a fixture with a realistic `ghp_…` token is rejected, and the reorg commit is not.
- **`dot:check`: the regression contract** (`mise-tasks/dot/check`, run as `dotrun dot:check`). Behaviors 1–5 below hard-fail; behavior 6 only warns.
  1. `bash -lc` resolves `mise ruby node flyctl` and sets `PGHOST PGDATA GOPATH`.
  2. An interactive login shell (`bash -lic`, as kitty's `bash --login` does) defines `switch dns first_of meta` and the `ll` alias, sets PS1, and writes nothing to stderr. These probes run under `script -qc`, so the job-control warnings that appear without a TTY don't count.
  3. `~/.bashrc.local` is sourced.
  4. There are no dangling symlinks at depth 1 in `~` and `~/.config`.
  5. `mise -C ~/code/dotfiles dot status --missing` exits 0.
  6. Startup: dot:check takes the median of 5 runs of `bash -ilc exit` and prints WARN above 0.15 s, without failing (baseline 0.09–0.10 s).

  After phase 1, it also asserts `push.default = simple`. `DOT_CHECK_PROFILE=container` skips the machine-specific assertions (`flyctl`, `PGHOST`, `PGDATA`). Before the repo `mise.toml` exists, run it by path: `bash mise-tasks/dot/check`. It must be green before phase 1 (minus intended differences) and after every phase, and doctor runs it.

### Doctor (`mise-tasks/doctor`, run as `dotrun doctor`)

Bash, read-only, and it exits non-zero when anything is undecided. It reads the declared set from `mise -C ~/code/dotfiles dot status --json`, never by parsing TOML. It reports:

1. Declared entries that aren't applied (`dot status --missing`, `bootstrap status --missing`).
2. Entries in `~/.config` (131 today) that are neither declared nor listed in `~/code/dotfiles/doctor.ignore`. Most are app state (Slack, Steam, chromium), so the first run is long. Working through it *is* the cleanup pass.
3. Files in `~/bin` that aren't the repo symlink, and repo `bin/` files missing the shebang or executable bit.
4. Symlinks in `~` and `~/.config` that point into the repo at paths that no longer exist, plus any symlink into `~/.asdf` (`~/.pgdata` does today, see phase 5).
5. Machine AI configs present but undeclared: `~/.claude/settings.json`, `~/.claude/statusline-command.sh`, `~/.config/opencode`, `~/.config/Cursor/User/settings.json`, `~/.config/Code/User/settings.json`.
6. gitleaks findings in adopted dirs (redacted), and `core.hooksPath` not set to `githooks`.
7. `dot:check` failures.

Each finding prints the next command with absolute paths, for example `dot add --local --source config/kitty ~/.config/kitty` or `echo kitty >> ~/code/dotfiles/doctor.ignore`. `~/.local/bin` is excluded, since installers own it (mise, claude, aws).

### Phases

Execution order: **0 → 1 → 2 → 4 → 3 → 5**. Doctor and adoption come before bootstrap, because doctor pays off weekly and bootstrap on reinstall day.

0. **Spike: pin mise's behavior (before anything moves).** Record `mise --version` and the `--help` output of `mise dot`, `mise dot add`, `mise dot apply` and `mise bootstrap` in `docs/mise-notes.md`. Use one scratch HOME for every probe: `export SCRATCH=$(mktemp -d)`, then `HOME=$SCRATCH mise trust <scratch-repo>` first. Probe:
   - symlink mode, copy mode, and `dot add --local --source` recording a repo-relative source, then copying edits back in copy mode;
   - block (managed partial-file) edits and the markers they write;
   - `apply` against an existing real file, a correct symlink and a dangling symlink (expected: prompt, `--force` overwrites, no backup);
   - `mise -C <dir> dot status --json`;
   - `mise bootstrap --from file://<bare clone>?ref=<branch> --from-dir <dir>`, with the root `mise.toml`;
   - whether `mise bootstrap` installs global tools from `~/.config/mise/config.toml`;
   - `gitleaks dir --redact` on today's tree, to seed `.gitleaks.toml`;
   - doctor's seeded cases (a stray `~/.config` dir, a stray `~/bin` file, a dangling link, an undeclared AI config, a fixture token, an unapplied entry), each reported;
   - the phase 1 restore script returning every link to its old target;
   - `dot add --dry-run --local --source config/kitty ~/.config/kitty` landing in the repo.

   Confirm that `[bootstrap.apt.sources]`, `[bootstrap.packages]` and `[bootstrap.mise_shell_activate]` exist. Anything missing gets the fallback named in its key decision. **The Rakefile stays until phase 1's checks pass.**
1. **Skeleton (on `darren/modernize`).** Precondition: `git status --porcelain` is empty, because the in-flight work is already merged. `bash mise-tasks/dot/check` is green. Steps, in order:
   1. Inventory every symlink in `~` and `~/.config` that points into the repo (`find ~ ~/.config -maxdepth 1 -lname '*code/dotfiles*'`). Save it as a restore script, `~/dotfiles-links-before.sh`, kept outside the repo, with one `ln -sfn <old-target> <link>` per entry. Mark each entry **deployed** or **retired**. Retired: `~/.spacemacs` (spacemacs goes to `archive/`) and `~/.gitignore` (merged into `config/git/ignore`).
   2. Write the repo-root `mise.toml` with `[dotfiles]` entries for the deployed entries, pointing at the *new* paths. Commit it on `darren/modernize`, so no recovery step can delete it. (You approve this commit like any other.) Run `mise trust`.
   3. Move the git-ignored machine-local files out of the tree. `bashrc.d/local.sh` becomes `~/.bashrc.local`, and `bash_profile.d/local.sh` (if present) becomes `~/.profile.local`. In the same change, before the move, add the sourced-if-present lines to the current `bashrc` and `bash_profile` (still at the repo root; step 4 moves them). Open a new terminal to confirm the local settings still load.
   4. Copy every conflicting non-symlink target to `~/dotfiles-bak`, including `cp -a ~/.config/mise ~/dotfiles-bak/mise`. With a recovery shell already open, run `git mv` into `home/`, `config/`, `templates/`, `docs/`, `archive/`, then `dot apply`, back to back.

      Recovery covers both outcomes, a failed apply and a partial one: in the open shell, `git reset --hard HEAD && bash ~/dotfiles-links-before.sh`, then restore `~/.config/mise` and the `local.sh` files from `~/dotfiles-bak` and the `.local` copies.
   5. Write `config/git/config` (`push.default = simple`, `editor = vim`) and `config/git/ignore`. Strip the GENERATED blocks from the live `~/.gitconfig` and `~/.gemrc`. Remove the retired `~/.gitignore` and `~/.spacemacs` links now, together with the new ignore file.
   6. Only after the checks pass, delete the Rakefile.

   Checks:
   - `dot diff` showed only source-path changes before the apply;
   - `dotrun dot:check` is green, now including `push.default = simple` from `~/.config/git/config`;
   - the retired links are gone.
2. **Scripts and shell layers.**
   - Pull the `~/bin`-only scripts into `bin/`, move AppImages out, and replace `~/bin` with a symlink.
   - Move the function candidates out into scripts.
   - Split `bash_profile.d` into `profile.d` (env/PATH) and numbered `bashrc.d` (interactive), per the table.
   - Add `profile.d/ssh.sh` and delete the ssh-agent block.

   Check: `dotrun dot:check` is green (both shell kinds); every old command still resolves (`type -a <name>` for each); `ssh-add -l` and `ssh -T git@github.com` succeed. If the ssh checks fail, use the SSH fallback.
4. **Adopt and doctor.**
   - Write `mise-tasks/doctor`, `doctor.ignore`, `.gitleaks.toml` and `githooks/pre-commit`, and set `core.hooksPath`.
   - Adopt kitty, nvim, gh `config.yml` (never `hosts.yml`), opencode, `claude/settings.json` and the statusline, each with `dot add --local --source …`.
   - Before each adopt, run gitleaks on the file; you look at any match yourself.

   Check: the fixture-token commit is rejected in a scratch worktree; `dotrun doctor` lists only entries you haven't decided on yet.
3. **Bootstrap.**
   - Translate `LINUX_README.sh` and `etc/sources.list.d` into `[bootstrap.apt.sources]` / `[bootstrap.packages]` (only what you still want; the rest goes to `archive/`).
   - Add the `bootstrap` task: it creates `~/.psqlrc.local` and sets `core.hooksPath`. Do **not** add `[bootstrap.mise_shell_activate]`: it refuses to edit `~/.bash_profile` when that's a symlink, which it is here [measured: phase 0]. Activation stays in `profile.d/mise_shims.sh` and `bashrc.d/mise.sh`.

   Check in a fresh `ubuntu:24.04` container:
   - `curl https://mise.run | sh`;
   - `mise bootstrap --from file:///src/dotfiles.git?ref=darren/modernize --from-dir ~/code/dotfiles --dry-run`, then `--yes`. `/src/dotfiles.git` is a bare clone of the local checkout, bind-mounted read-only, because the branch isn't pushed;
   - `cd ~ && ruby -v`;
   - `DOT_CHECK_PROFILE=container dotrun dot:check`.

   If `--from` rejects `file://`, the container test alone falls back to clone + `mise trust` + `mise bootstrap`.
5. **Your cleanup pass.** Go through `archive/` and the doctor list file by file: keep, ignore, or delete. Done when doctor exits 0. **Do not delete `~/.asdf` until PGDATA is moved out**, because `~/.pgdata` points to `~/.asdf/installs/postgres/18.3/data/`. Moving it means reinstalling postgres under mise and migrating the data, or relocating the data dir.

## Open Questions

- Which apps break symlinks by rewriting their config? Test each adopted app (edit a setting in its UI, then `ls -l`) before choosing `copy`.
- Bash long-term? `~/.config/fish` exists. A shell change is out of scope here, but the numbered `bashrc.d` keeps it cheap later.
- Does `mise bootstrap` handle `apt` sources with keyrings (`signed-by`) for Chrome, Heroku and Enpass the way the docs suggest? Verify in the phase 3 container.

## Success Criteria

- No `Rakefile`, and nothing in the repo needs Ruby before bootstrap.
- In a clean Ubuntu container, the `mise bootstrap --from` command produces a working login shell with prompt, aliases, `bin/` on PATH and mise tools, and `DOT_CHECK_PROFILE=container dotrun dot:check` passes.
- `dotrun dot:check` is green on this machine after every phase.
- `dot status` reports every entry applied on this machine.
- Each script exists once, and `readlink ~/bin` points to the repo.
- `dotrun doctor` exits 0 after your cleanup pass.
- `git config --show-origin --get-all push.default` prints exactly `simple`, from `~/.config/git/config`.
